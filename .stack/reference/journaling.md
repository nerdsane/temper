# Work journals

Use for implementation and other work with an existing journal requirement; ordinary answers do not create a goal.

- For real work that requires a journal, keep one OKF file per goal under `~/Garden/journal/work/`. Frontmatter: `type: work_summary, id, domain, goal, objective, key_result, runtime, started_at, state`. `objective` and `key_result` are OKR codes or `none`.
- Record milestones as they happen using concrete results and links. Close the record with `state: done` or `abandoned` and `ended_at` when the work ends, then commit and push it. If offline, retain the change in Garden and report that it has not been pushed.
